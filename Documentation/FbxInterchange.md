# FBX 导入导出规范

本规范适用于静态网格、骨骼、蒙皮网格、骨骼动画，以及包含这些资产的组合导出。
FBX 是交换文件；SharpEngine 的可读资产数据是导出依据。验收目标是生成语义等价的新
FBX，不要求文件字节、SHA-256、对象编号、记录顺序、压缩方式或工具版本信息一致。

## 等价范围

等价比较的基准是当前选定的 SharpEngine 资产。首次导入时，必须说明支持的 FBX 数据
范围及转换方式；不能把只保留几何的导入称为完整 FBX 无损往返。

| 资产 | 必须保留的语义 |
| --- | --- |
| Mesh / StaticMesh | 顶点位置、三角形连接与朝向、坐标系、单位，以及资产已经支持的材质关联 |
| Skeleton | 骨骼身份映射、名称、父子关系、局部绑定 TRS 与由此计算的世界绑定姿态 |
| SkeletalMesh | 网格语义、关联骨骼、绑定姿态、每顶点骨骼影响及归一化权重、绑定后的形变结果 |
| SkeletalAnimation | 片段身份映射、时长、采样率、骨骼关联、局部 TRS 轨道、根骨运动及采样姿态 |

FBX 中尚未被引擎资产建模的 UV、法线/切线、材质细节、纹理、约束、控制器、形变键、
相机、灯光和自定义属性，不自动获得往返保证。导入器必须报告省略或烘焙的内容；遇到
无法表达且影响声明语义的数据必须拒绝，或要求显式的有损转换选项。导出不得省略
当前 SharpEngine 资产已经保存的语义字段。

## 导入

1. FBX 来源位于 Content 之外；只将导入后的引擎资产注册进资产清单。来源不成为
   Runtime/Cook 的隐含权威数据。可选来源校验字段仍会让对应加载路径依赖来源文件。
2. 先解析、归一化、完整校验，再提交资产和清单。多个关联资产作为一个导入结果校验，
   失败不得留下部分发布结果。资产和清单写入临时文件，校验成功后再替换目标。
3. 统一到引擎 Y-up、右手系、-Z 前方；交换约定为一个长度单位等于一米，时间以秒计。
   FBX 的轴与单位设置、节点变换必须只换算一次；负缩放转换同时修正三角形朝向。
4. 静态几何可以烘焙节点变换。骨骼保存父级局部绑定 TRS，蒙皮位置、绑定矩阵与
   动画轨道必须使用相同空间，不能分别套用不同的轴变换或重复单位缩放。
5. 所有骨骼引用必须可解析，层级无环。关键帧时间严格递增且位于片段时长内；
   缺失轨道采用资产规定的绑定姿态。根骨位移不能被隐式删除或转移到外层节点。
6. 当前蒙皮契约每顶点支持 1–4 个影响。超过上限的源数据不得静默截断；需拒绝，
   或明确报告截断与归一化规则。非有限值、无效索引和非法变换必须拒绝。

### 来源字段

`sourcePath` 与 `sourceSha256` 是成对可选的来源校验字段，适用于以上四类规范化资产。
路径相对于所属引擎/项目根目录，使用 `/`，禁止越界；哈希是导入时来源字节的 SHA-256。
未提供字段的资产可以独立加载。提供时必须进行路径、文件存在性与来源哈希校验。

来源哈希只能证明来源文件没有变化，不能证明后来编辑的网格、骨骼或动画仍与来源
等价。它也不要求导出的新 FBX 与来源哈希一致。程序生成的走/跑/跳动画不能仅因沿用
同一骨骼，就把不包含这些动画的原始 FBX 声明为该动画片段的完整来源。

资产 JSON 的 schemaVersion 仍为 1；骨骼动画增加可选来源字段并保持旧 v1 资产可读。
原有七参数动画构造函数保留，新九参数重载接收来源字段。新解析器继续拒绝未知字段、
重复字段和未来 schema；旧解析器不承诺读取带新字段的资产。

## 导出及组合选择

1. 导出读取同一已提交版本的当前资产数据。未保存的编辑如果属于导出选择，必须先
   捕获一致快照；不能混用部分内存数据和部分过期磁盘文件。
2. 一次导出可以选择静态网格，或一个兼容骨骼组中的骨骼、多个蒙皮网格和多个动画。
   蒙皮/动画所需骨骼属于必要依赖；共享骨骼只写一次，每个动画写成独立片段/take。
   单独导出动画也要带能解释轨道的骨骼层级与绑定姿态。
3. 用稳定骨骼身份及父子/绑定关系校验兼容性，不能只按骨骼数量、文件名或来源哈希
   合并。不同骨骼组分别导出，或明确拒绝合并；不隐式重定向、重定根或重定向动画。
4. FBX 内部编号和顶点编号允许重排，但必须同时重映射拓扑、蒙皮及轨道引用。
   导出报告保留资产与 FBX 对象/片段的对应关系。重名造成映射歧义时明确报错。
5. 可以烘焙动画曲线，但必须保留动画求值语义。引擎的线性位置/缩放插值和四元数
   Slerp 不能直接冒充等价的欧拉角线性曲线；重采样后按姿态和蒙皮结果验收。
6. 在临时路径生成并验证新 FBX，成功后再发布；失败保留已有输出。不依赖保留来源
   文件才能重建资产，不得用过期来源副本替代当前资产或漏掉后加的动画。

### 显式 Retarget

普通动画绑定不会隐式重定向。`SkeletalAnimationCompatibility.Validate` 会先检查动画和
蒙皮网格的 `SkeletonId`，再检查动画内嵌骨骼的身份、父子关系和绑定局部 TRS；A 动画不能
直接驱动 C 蒙皮网格时必须报告错误。

需要跨骨骼组复用动画时，调用方显式提供 `SkeletalAnimationRetargeter.Retarget` 的源骨骼、
目标骨骼和完整的源到目标骨骼映射。Retarget 会生成一个新的动画资产，将 `SkeletonId` 指向
目标骨骼，并按源/目标绑定姿态换算每个关键时刻的局部 TRS。随后再对生成动画、目标 Skeleton
和目标 SkeletalMesh 做普通兼容性检查；验证通过后才算得到 C 组的可组合动画。

当前映射不自动按名称猜测，也不包含 IK、姿态匹配、链长比例补偿、脚底贴地、根骨策略、
坐标系/单位配置或 FBX writer。源动画保持不变，Retarget 输出是独立资产；映射本身尚未保存
为独立资源。

这些规则定义组合导出的目标契约；当前尚无编辑器多选 pack 导出命令或组合 writer。

## 回读验收

重新导入生成的 FBX，使用明确的骨骼/顶点/片段映射比较以下结果。不能只检查文件存在、
能被工具打开或 SHA-256。

| 比较项 | 默认容差/要求 |
| --- | --- |
| 骨骼身份、名称、父子关系、片段集合及引用 | 映射后精确一致，无缺失和歧义 |
| 绑定/动画平移、几何与形变顶点 | 每分量绝对误差 ≤ 1e-5 米 + 1e-5 × 比较值绝对值 |
| 单位、朝向、拓扑和三角形正反面 | 归一化并重映射后保持一致 |
| 旋转 | 归一化四元数比较，允许 q 与 -q；角度误差 ≤ 1e-3 弧度 |
| 缩放、蒙皮权重 | 每分量绝对误差 ≤ 1e-5；影响与权重须一起重映射 |
| 时长和关键时刻 | 误差 ≤ 1e-6 秒，采样率记录一致 |

动画检查覆盖起止点、源关键帧、相邻关键帧中点及按采样率生成的时间点，并比较局部
姿态、世界骨骼矩阵与蒙皮形变结果。允许项目显式配置更严格或特定尺度的容差，报告
必须写明实际容差、最大误差、烘焙策略、丢失数据诊断及导入/导出工具版本。

## 当前实现边界

- `Tools/Assets/ImportStaticFbx.py` 是 Blender 静态几何导入器，只保存三角形几何、
  配置的默认材质引用及可选来源字段；骨骼、蒙皮和动画没有通用 FBX 导入器。
- `FbxSourceContract.ExportFbx` 及各资产包装方法定义语义导出入口。当前原始
  `FBXSource` 可以复制；规范化引擎资产会抛出 `NotSupportedException`，且不修改输出。
  真正的 FBX 重建 writer 尚未实现。
- `ExportOriginalFbx` 保留原来的来源复制行为并标记 obsolete。它只验证并复制来源，
  不包含当前资产编辑结果，不是语义导出的兼容别名。
- 骨骼、蒙皮和动画 JSON 回读、Runtime 测试不代表已经完成 FBX 重建与回读验收。
