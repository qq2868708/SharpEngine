项目入口与插件启用契约

项目构建通过 SharpEngineProjectBuildRoot 标识暂存上下文；插件输出只能位于该项目的 Intermediate/.../ProjectBuild，中间产物只能位于 Intermediate/.../Modules，来源限项目 Source/Plugins 或引擎 Plugins。SEOUTPUT015–SEOUTPUT017 校验这些边界；普通引擎构建继续使用原输出目录约束。

engine.json schema 2 的可选 plugins: string[] 仅接受 engine://Plugins/.../*.sharpplugin；项目 schema 3 的 plugins 与 disabledPlugins: string[] 支持 engine/project URI。有效集合为“引擎默认项 ∪ 项目启用项 − 项目禁用项”；同一项目内显式启用与禁用同一 URI 是错误。新增项目显式保存两个空数组。插件 ID 保持稳定且跨作用域唯一，依赖来自 MSBuild 求值后的 Module ProjectReference，不再维护重复的插件依赖清单。

Project Selector 无参数或 browse 打开选择窗口；preview-project --project <manifest> 只读取已保存元数据。项目的可选 previewImage 是项目目录内已有图片的相对路径；最近项目缓存位于用户 LocalAppData 的 SharpEngine/projects.json，schema 1。plugins 列出有效启用状态；plan-plugin --project <manifest> --plugin <id> --action enable|disable 返回 schema 1 的 planId、changes、blockers，变更项带 clearsExplicitDisable。apply-plugin 使用同一参数并要求 --expected-plan <planId>；状态或依赖输入已变化时以 SEPLUGIN031 拒绝。命令支持 --engine-root、--no-ui、--output；新查询命令和计划使用 camelCase JSON。

计划覆盖项目已启用的 Target 和 Debug/Development/Shipping 配置，跟踪项目、引擎、插件清单、模块工程和 MSBuild 导入。依赖循环为 SEPLUGIN029，不可禁用依赖为 SEPLUGIN030。配置属 authoring 权威数据，依赖图和计划属派生数据；UI 与 CLI 共用计划/提交路径，通过项目锁、输入校验和临时文件原子替换保存，保留无关字段。配置操作立即保存项目清单，不进入 World Undo 栈。Editor 的 File → Project Plugins... 与 MCP plugins.describe/plugins.request 共用管理状态与相同 CLI 计划/提交后端；request 带 expectedRevision，支持 analyze、plan-enable、plan-disable、apply、cancel，apply 还要求精确 expectedPlan 且必须 Stopped。保存后 restartRequired 阻止自动代码激活，直到重启，不在当前进程热卸载插件。

modules.runtime.json schema 2 新增 enginePluginsHash，引擎默认插件改变或旧构建缺失该字段时要求重建项目；DLL 和插件清单继续接受构建完整性校验。无项目的 Engine.exe 进入自身的轻量 RmlUi 选择器；显式 --project-browser 也进入该模式。--mcp-isolated 和 editor.session.launchIsolated 必须显式提供项目，后者的 projectManifest 为必填非空字符串。Engine.exe --mcp-stdio 仍是无 EditorRuntime 的 Editor 会话桥接入口。选择器使用 SharpEngine.ProjectSelector.exe --mcp-stdio：未绑定连接仅暴露 projectBrowser.sessions.list、projectBrowser.session.attach 和 projectBrowser.session.launchIsolated，一条连接绑定一个明确选择的会话；launchIsolated 可指定独立的 recentFile 并在引擎中启动隐藏选择器。绑定后发现 browser.describe、browser.command、ui.describe、ui.pointer、ui.key，资源为 sharpengine://project-browser、sharpengine://ui 及同帧 PNG 模板 sharpengine://ui/frames/{frameId}/{hostId}.png。browser.command 带 expectedRevision，支持 preview/show-create/create/open/close。原 Game MCP 的工具 ID、会话选择协议和资源 URI 保留，底层 UI 传输共用 UiMcpSessionHost。Browser/Game 的 modifiers 数值映射通过 inputSchema 的 x-sharpengine-modifiers 自描述（control=1、shift=2、alt=4）；Editor 仍使用名称数组。UI 验收只通过 MCP 的真实输入、frameId/expectedElementId 和同帧 PNG，不使用桌面控制。源码：PluginConfiguration、PluginGraph、ProjectBrowser。

API 条目

SharpEngine.Runtime

RuntimeWorld、World、组件注册、实体和序列化入口。Authoring 数据是权威状态，Runtime World 从最近提交快照重建。

相关稳定身份包括 engine.transform、engine.camera、engine.static-mesh 和已注册的项目组件 typeId。

SharpEngine.Build.props 输出契约

引擎源码工程把 Configuration、SharpEnginePlatform、SharpEngineTarget、SharpEngineOutputTarget 及所有最终/中间输出路径作为 project-local 权威属性。调用方请求会先被记录，再恢复为规范路径；ValidateSharpEngineOutputContract 在 restore、依赖解析和 PrepareForBuild 前拒绝不一致请求，因此非法全局属性不能先创建目录再失败。

允许的 configuration 为 Debug、Development、Shipping，允许的 output target 为 Editor、Game、Server、Tools。最终输出位于 Binaries/Win64/<Configuration>/<Target>，中间输出位于对应 Intermediate 层级；Intermediate/RenderCache 是精确命名的共享派生缓存。验证输出使用 Saved/Validation。BuildRenderShaders.ps1 只接受规范 target shader 目录或 Saved/Validation。

SharpEngine.Editor.EditorRuntime

提供 Editor 生命周期、场景/资源/编辑器快照、命令注册和项目代码重载的语义入口。编辑器命令同时服务 UI 点击和 MCP 调用；Content Manager 条目使用 editor.content.select-folder:<pane>:<source>|<path> 选择文件夹，双击动作使用 editor.content.open:<pane>:<source>|<path> 进入文件夹。除 World 外的内置可编辑资源通过 IAssetEditorInstance 和 AssetEditorHost 建立独立顶层编辑器根。

IMenuExtension、IToolBarExtension 和 ICustomBarExtension 分别扩展固定 File 菜单、主 Toolbar 和引擎创建的 viewport/timeline CustomBar。CustomBar 的 Append/Replace 只影响显示，命令注册仍然保留；扩展不能创建或删除顶层 Surface。

RenderCore retained GPU scene

GpuSceneVertex、GpuMeshUpload、GpuSceneDraw 和 GpuSceneFrame 是 Editor 与 Game 共用的 native submission contract。Native Host API v13 增加 EnsureGpuMesh/SubmitGpuScene；v14 追加只读 GetRenderStats；v15 在 GpuSceneFrame 中增加由场景组件派生的 SkyRadiance；v16 将 GpuSceneVertex 扩展为 12 组骨骼索引/权重（120 bytes）。字段仅在同步调用期间借用 managed 地址，GPU handle、descriptor、buffer 和 frame slot 不进入序列化状态。Vulkan 的每个 RenderBackend_Vulkan::Surface 持有独立 RmlUiVulkanDeviceContext，其中保存 Instance、Device、Queue、Swapchain 和帧同步句柄；RmlUi adapter 只借用该 context 录制 UI。

engine.sky-light 是内置组件 schema v1，权威字段为 Color 和非负 Intensity。Authoring state 通过通用组件事务、revision、Undo/Redo 和显式 Save 管理，并在 Runtime 重建；渲染帧只累加 enabled 且 active-in-hierarchy 的实例。Sky Light 不持有天空盒、Cubemap 或 GPU 资源，当前也不生成可见背景。

GpuMeshPayload 是 schema-independent derived cache payload，当前 PayloadVersion = 3，包含展开的 flat-shading 顶点、每顶点最多 12 个蒙皮影响、section/BoneMap、Bounds 和 BVH。每个 section 的 BoneMap 最多 256 项；构建器按三角形稳定顺序自动切分，不能把该数值解释为资产骨骼上限。缓存位于 Intermediate/RenderCache/<contentHash>.sgpumesh，源资产仍是唯一权威。

RenderOptions 解析 --render-backend=opengl|vulkan、--render-vsync=on|off 和 --render-validation=on|off；RenderInitDesc.EnableVSync/EnableValidation 把 transient 选择传给每个 Editor surface 和 Game backend。VSync 默认 true；显式 off 如果不能真正选择无阻塞 swap interval 或 immediate/mailbox present mode，初始化必须失败。Validation 默认 false，只有定义了 validation 支持的 Vulkan Debug target 接受 true。

render.describe 和 sharpengine://render 返回 schema v1 transient snapshot：backend、vsync、validation、gpuScene、cache、timingMilliseconds、native 和 diagnostics。timing 窗口最多 240 帧并同时返回 average/P95；能力 effect 为 read，不创建 revision 或事务。

SharpEngine.Runtime.Input

InputAction、InputMappingContext 和统一输入路由。动作回调返回 true 时消费动作；事件顺序和 route 名称属于可观察契约。Win32/RmlUi 修饰键位遵循 Ctrl=1、Shift=2、Alt=4；编辑器 Play 状态下，Host 不再把事件转发到 EditorRuntime 的 Viewport 导航、选择或 Gizmo 入口。

InputAssetEditorInstance 编辑 schema v1 的 action/context 字段与 binding 数组；每次变更重新校验稳定 ID、枚举、Control 语法、modifier 和 InputAction 引用，再提交文档 revision。

SharpEngine.Animation.AnimationStateMachineAsset

状态机资源使用 .sanimationstatemachine 和 schema v1，保存稳定的参数、状态、Clip 依赖和有序过渡。AnimationStateMachineContent.Load 先解析完整图并绑定所有骨骼动画；AnimationStateMachineAsset.SelectTransition 按资源顺序检查 exitTime 和数值条件。engine://animation-state-machines/uefn-mannequin-locomotion 在 engine manifest 中以 readOnly=true、builtin 和 preset 标签登记，并声明 mannequin skeleton 与四个 Clip 依赖。

Content Manager 的双击和语义打开都调用 EditorRuntime.OpenAsset；统一的 EditorAssetOpenerRegistry 通过 engine.animation-state-machine-editor 将该类型路由到独立顶层动画资产编辑器。状态图、Preview 和 Details 都是该编辑器根拥有的普通 Pane。

AnimatorComponent schema v3 的 Controller、StateId、Parameters、MovementSource 和 MovementSpeedParameter 是权威字段；运行帧 schema v2 公开当前状态、过渡、参数和采样结果。旧 Animator v1/v2 只补齐控制器字段，不改变既有单 Clip 语义。

Player、第三人称与 Root Motion

engine.player-controller schema v2 追加 InputContext、MoveAction、LookAction、ViewCamera、FacingMesh、FaceMoveDirection、TurnSpeed。v1 显式迁移；RuntimeInstance 接收 IInputRuntime/InputHostId，组件持有 activation/handler 生命周期。engine://input/contexts/player 映射 player.move、player.look、player.release-pointer，新文件后缀为 .sinputaction/.sinputmappingcontext；旧后缀继续读取。

engine.third-person-camera schema v1 字段为 Target、TargetOffset、Distance、Yaw、Pitch、LookSensitivity。相机在根运动和 Movement 提交之后更新，Runtime 活动相机优先使用 LocalPlayerController.ViewCamera。editor.describe.playInputCapture 与 input.describe.capture 公开捕获状态；--mcp-visible 可显示隔离 Editor 进行真实焦点验收。

SkeletalAnimationAsset schema v2 保存 AnimationRootMotionSettings。Sample 保留原始轨道语义，SamplePreview、RootMotionSampler.RemoveRootMotion/Delta 提供开关输出和连续增量；Animator 组件 schema v3 不变，帧 schema v4 增加 rootMotion（含 consumedBy）。RootMotionSampler.Delta 把循环展开为一条绝对曲线，跨周期的一帧按“剩余周期 + 新部分周期”的顺序合成。根设置与 Notify 使用同一资产历史，语义命令为 root-motion；保存使缓存失效。完整约束和诊断见 动画专题。

移动权威与 Character Movement 插件

SharpEngine.Components.IMovementAuthority 是引擎提供的移动组合点。帧末边界按 BeginMovementFrame → ConsumeRootMotion → EndMovementFrame 调用，全部 Evaluate 已完成且任何 LateUpdate 相机尚未运行。持有权威的实体不再收到引擎内建的根运动写入，同实体的 engine.movement 转为 MOVEMENT_OVERRIDDEN，保证 Transform 只有一个写入者。同一实体出现两个权威时报告一次 MOVEMENT_AUTHORITY_CONFLICT 并按组件 ID 保留第一个。

RootMotionContribution 公开 animator 组件 ID、目标实体、网格组件、目标世界矩阵、网格相对矩阵、世界增量、世界位移、播放推进量和 DeltaSeconds。ConsumeRootMotion 返回 true 表示权威接管本帧根运动，animator 帧发布 ROOT_MOTION_CONSUMED 并记录 consumedBy；返回 false 时引擎按内建路径应用。

Plugins/CharacterMovement（sharpengine.character-movement，schemaVersion 1）以插件包形式提供整套角色移动：CharacterMovementComponent 是权威，WalkingMovementModeComponent/FallingMovementModeComponent 是按 GroundModeId/AirModeId 选择的模式，Jump/Sprint/SpeedLimit 修饰器按 Priority 组合，模式身份由 CharacterMovementModeIdAttribute 声明。插件为项目级 opt-in，需在 .sharpproject 的 plugins 数组登记 engine://Plugins/CharacterMovement/CharacterMovement.sharpplugin；引擎默认内容不引用插件组件。

SharpEngine.Components 控制与移动

ControllableComponent、ControllerComponent、PlayerControllerComponent、AiControllerComponent 和 MovementComponent 中 PlayerController 使用 schema v2，其余保持 v1。控制器通过 SetMoveInput 提交当前帧意图；移动组件依赖 Transform 和 Controllable，并发布稳定的诊断 code 与速度 frame state。

绑定仲裁、运行时字段和示例见 控制、可控制目标与移动专题文档。

prefabs/capsule-character

资源类型为 Prefab，源文件为 Content/Prefabs/CapsuleCharacter.sprefab，使用 World/Prefab JSON schema v3。Mesh 子实体包含 engine.skeletal-mesh（engine://meshes/uefn-mannequin）；根实体包含 engine.animator、engine.capsule-collider、控制与移动组件；engine.player-controller.ControlledEntity 指向根实体稳定 ID，实例化时必须重映射实体和组件引用。

示例 Prefab 使用 engine.skeletal-mesh schema v1（engine://meshes/uefn-mannequin）和 engine.animator schema v3，绑定 engine://animation-state-machines/uefn-mannequin-locomotion。实例化同时重映射 Target 和 MovementSource；胶囊 collider schema v1 提供 RuntimeWorld.Collision.Raycast 查询且不生成渲染几何。动画复用 Playable 采样，SkeletonFrameState 的骨骼矩阵和蒙皮顶点属于派生帧数据，不保存进 Prefab/World。

AssetPreviewWorld / WorldViewportLayout

资产编辑器持有临时 AssetPreviewWorld.World；WorldViewportLayout 复用布局、导航与渲染入口，调用者传入 World。Frame 显式取景，Render 使用标准场景渲染，TryHandleAction 接收宿主路由的相机输入；Describe 暴露瞬态预览场景与相机状态，均不保存进资产。源码：AssetPreviewWorld.cs、WorldViewportLayout.cs。

SharpEngine.Timeline

IPlayable、PlayableGraph、TimelineDocument、TimelineView、TimelineAuthoringSession、AnimationNotify 和 MarkerPlayable。每个 TimelineAssetEditorInstance 拥有独立播放、选择、Undo/Redo 和 dirty 状态；资产编辑器命令通过所属 hostId 路由。Preview 是不可游离的主 Pane，Timeline 与 Details 是同一 EditorRootId 下的普通 Pane。

TimelineView 持有当前时间、播放状态和推进逻辑，提供 Play/Pause/Stop/Seek/Update，通过 TimeChanged 与 PlaybackChanged 供外部订阅。TimelineTimeChangedEvent 带 timelineId、前后时间和 Playback/Seek/Stop 来源。Seek 暂停且连续定位，不保存或恢复拖拽前的播放状态。插件订阅事件后自行处理预览；通用时间轴不执行业务 Notify，动画编辑器也不执行 Notify。播放数据属于瞬态状态，Timeline 资产 schema 仍为 v1。TimelineViewState.CurrentTime 通过 Seek 修改，避免绕过事件。源码：TimelineView.cs、TimelinePlayback.cs。

SharpEngine.Networking

NetworkSchemaCatalog 登记稳定的组件属性和 RPC 描述；NetworkCommandRouter 只执行显式注册的 Command，并按 ConnectionId + MessageId 缓存幂等结果。

NetworkReplicationFrameBuilder 从不可变 RuntimeFrame 生成完整快照或基于 NetworkReplicationBaseline 的字段差分。DedicatedServerSession 运行权威 Runtime Tick 并返回 NetworkServerFrame。

UdpNetworkTransport 基于 LiteNetLib 提供 C# UDP、MTU 分片、CRC32C、连接超时、四种可靠性和四条通道；DedicatedServerNetworkHost 提供 Schema 指纹握手、Command 权限入口、每连接 baseline/ACK；NetworkClientSession 和 NetworkReplicaState 提供客户端握手、Command 发送和原子快照应用。当前协议版本为 NetworkProtocol.SchemaVersion = 1；QUIC、生产认证和客户端预测不属于本阶段公共实现。

INetworkServerRuntime 是 Server Runtime Module 的注册契约，提供 NetworkSchemaCatalog、RegisterCommand、权限和相关性策略入口；Server Target 的原生入口为 DedicatedServer.exe。项目 manifest 的 targets 数组控制生成的 Target；默认值为 ["Editor", "Game"]，Project Selector 的 add-target --target Server 和 remove-target --target Server 原子更新该契约。Windows 文件关联的 AddServerTarget 和 RemoveServerTarget shell verb 分别调用这两个命令，随后自动重新生成工程文件。

EditorAssetOpenerRegistry

Register(EditorAssetOpener) 注册按 AssetType 或具体 AssetId 匹配的打开器，并返回可释放句柄；具体资源优先于类型匹配，同级按 Priority 选择。返回 IAssetEditorInstance 的打开器会按 AssetId 创建唯一 AssetEditorHost；不同资产即使共享 EditorId 也拥有不同 EditorRootId。assetTools schemaVersion 2 的 editors 数组公开 editorId、openerId、rootId、assetId、dirty、只读状态、主布局、游离布局和实例状态。同一资产重复打开返回 ASSET_EDITOR_REUSED。

AssetEditorPaneDefinition、AssetEditorCommandDefinition 和 IAssetEditorInstance 定义顶层资产编辑器扩展契约。原生 UI host 快照公开 rootId，host kind 为 main-editor、top-level-editor 或 floating-tab。Dock 拖拽只接受相同 rootId；游离 Tab 保持原根所有权且没有独立 Menu/Toolbar。

内置 opener 覆盖 Mesh、StaticMesh、SkeletalMesh、Skeleton、Material、StyleSheet、InputAction、InputMappingContext、RmlDocument、Prefab 和动画类型。AssetType="*" 的低优先级 opener 只有在 CanOpen 匹配当前 DataAssetTypeRegistry typeId 时才创建通用 DataAsset 编辑器；具体类型 opener 始终优先。

JsonAssetAuthoringDocument 与 TextAssetAuthoringDocument

Editor-owned 文档会话保存独立 Revision、SavepointRevision、dirty、Undo/Redo 和加载时 source hash。结构化字段在提交前验证完整候选 JSON；文本字段允许保留带诊断的草稿，但有 error 时禁止 Save。Save 检查外部文件 hash，重新解析完整输出并通过临时文件原子替换。该状态位于 authoring/editor context，不进入 Runtime 或 Cook。

版本化 JSON 与 MCP

AI-facing snapshot、组件、资产、设置和输入契约包含 schemaVersion。未知未来版本、未知必需类型和迁移失败必须返回结构化诊断；不能静默丢弃字段。

SharpEngine.Assets.FbxSourceContract

ExportFbx(AssetRegistry, Id, Destination) 定义 Mesh、StaticMesh、Skeleton、SkeletalMesh 和 SkeletalAnimation 的语义导出入口。当前内置实现只复制显式注册的原始 FBXSource；规范化资产返回 NotSupportedException 且不修改目标。sourcePath/sourceSha256 只能校验来源未变，不能证明已经编辑的当前资产与来源仍然语义一致。接入 FBX writer 后，编辑后的规范化资产必须从当前数据重建。

StaticMeshAsset、SkeletonAsset、SkeletalMeshAsset、SkeletalAnimationAsset 和 AssetContent 都提供同名 ExportFbx 包装入口。旧的 ExportOriginalFbx 只作为标记为 obsolete 的来源复制入口。

SharpEngine.Animation.SkeletalAnimationCompatibility 与 SkeletalAnimationRetargeter

SkeletalAnimationCompatibility.Validate(Animation, Mesh) 是普通组合的显式检查：比较 SkeletonId、骨骼身份、父子关系和绑定局部 TRS；失败时抛出输入错误，绝不隐式重定向。

SkeletonAsset schema v2 增加显式可空 previewMeshId，作为 Editor-only 默认预览网格引用；schema v1 确定性迁移为 null。运行时动画组合仍只依赖 Skeleton 和显式 Mesh 组件，不读取该字段。

SkeletalAnimationRetargeter.Retarget 接收源动画、源/目标 Skeleton 和完整 BoneMap，创建新的 SkeletalAnimationAsset 并把 SkeletonId 指向目标 Skeleton。输出保留时长、采样率、Notify 和关键时刻，并通过绑定姿态 Delta 计算目标局部 TRS。当前没有 IK、比例补偿、自动命名匹配或独立 RetargetMap 资产；调用方应在输出后再次调用兼容性检查。

数据资产 API

DataAsset 支持抽象基类和继承属性；每个可加载的具体派生类型使用 DataAssetTypeAttribute 声明稳定类型 ID，sealed 可选。DataAsset<T> 是叶子类型的便捷基类，DataAssetFactory.Create<T> 可创建任意具体派生类型。DataPropertyAttribute、DataAssetTypeRegistry 和 DataAssetSerializer 定义第一阶段数据资产契约。.sdataasset 使用类型声明的 schemaVersion，封套包含 schemaVersion、kind、assetId 和 name；manifest type 等于稳定类型 ID。

支持显式注册与程序集发现、属性描述和 JSON Schema、确定顺序序列化、强类型加载、范围与直接引用校验、只读保护和临时文件替换。DataAssetTypeRegistry.Load<TBase> 会按 manifest 类型创建具体派生值并返回可赋给基类的实例。DataAssetEditorInstance 使用当前注册描述器生成一套通用反射表单，并把每次完整反序列化与约束校验纳入 Editor 文档事务；项目 Runtime Module 重载后描述器按 typeId 重新解析，不保留旧 CLR 类型实例。assets.describe 与 sharpengine://assets 暴露同一类型和 Schema。完整 Cook 仍不属于该 API。详见 数据资产专题。
