项目选择器与插件

直接启动引擎且未指定项目时，进入引擎自身的项目选择器，复用现有 RmlUi、标题栏、输入链路、图标和 Editor 配色；这一轻量启动模式不会初始化 EditorRuntime、加载 World 或执行项目插件。选择器提供最近项目、浏览、创建和静态封面预览，展示项目名称、路径、引擎版本与兼容状态。可以通过系统文件选择框浏览，也可以输入项目路径并点击“预览项目”。创建完成后选中新项目，点击“打开项目”进入其 Editor 并关闭选择器。指定有效 --project 可直接打开项目；无效项目报告错误，不会回退为空项目 Editor。

启动选择器仅提供项目操作。进入 Editor 后，通过 File → Project Plugins... 打开插件管理，点击“分析项目插件”：启用时分析并补齐直接、间接依赖；禁用时分析所有已启用的反向依赖。完整变更清单确认后一起保存，取消不会修改配置。仍被使用的共享依赖保留；项目代码或核心模块依赖会阻止禁用并显示依赖链。此前显式禁用的依赖会在启用预览中标出“撤销项目显式禁用”。更改后须重建项目并重新打开 Editor，不会动态卸载正在运行的插件。

引擎清单 plugins 提供默认启用项，项目清单的 plugins 添加启用项，disabledPlugins 排除插件；项目操作只修改项目清单，不改引擎默认项。代码构建与资源挂载使用相同的有效集合。直接编辑清单时也必须满足模块依赖；构建不会静默启用被显式禁用的依赖。

开始使用

创建或打开项目后，可以在编辑器中搭建场景、配置资源并预览结果，也可以启动独立运行模式检查游戏中的表现。

编辑器允许在没有现成项目内容时从空白状态开始；运行模式需要一个有效的启动场景。项目会记录所使用的引擎版本，保证团队成员看到一致的内容和行为。

编辑器工作流

引擎的通用基础设施与功能组合规则见 基础设施与组合层。

Mesh、Skeleton、Timeline、Material 和 Prefab 的 3D 预览统一支持右键环绕、中键平移、滚轮缩放与 Focus 取景。每个窗口拥有独立观察相机，导航不修改挂接 World 内的相机实体，也不改变资产的修改状态或撤销记录。Prefab 预览使用文档副本；资产实体编辑仍走原有撤销与保存流程。Material 直接挂接材质内容，保留现有颜色预览着色方式。

编辑器提供视口、层级、资源浏览、属性检查、界面编辑和日志查看等面板。播放会使用当前已保存的内容创建独立的运行副本；停止后，运行期间的临时变化会被清除。

层级、变换、资源选择和设置编辑都支持撤销、重做和恢复。编辑器会在内容变化后重新载入可用结果；如果载入失败，会保留当前编辑状态并显示诊断信息。

资源浏览器支持按文件夹、名称、来源和类型查找内容，多个浏览器可以分别保留自己的位置、筛选条件和选择。单击文件夹只选择它并保持当前目录，双击文件夹才进入目录；文件夹图标和名称遵循相同规则。资源仍然是单击选择、双击打开。

主编辑器和顶层资产编辑器是两个不同的编辑器根：两者都有自己的菜单、工具栏和 Dock 布局。主编辑器负责当前 World；动画、UI、Prefab、Mesh、Skeleton、Material、StyleSheet、Input 和项目 DataAsset 会按资产打开独立顶层编辑器。顶层编辑器内部的普通窗口只能在所属编辑器根内停靠，也可以脱离为仍归原根所有的游离 Tab；它们不能停靠到主编辑器或另一个资产编辑器。关闭有未保存修改的顶层编辑器时会先要求保存、放弃或取消；关闭主编辑器也会依次检查所有打开的脏资产编辑器，任一取消都会阻止退出。

动画时间轴与 Notify

骨骼动画使用专用 SkeletalAnimation 资产编辑器。Preview、Timeline、Details 保持可停靠编排，Preview 为主面板；播放、预览网格、Root Motion、Notify、Undo/Redo 与 Save 的操作方式保持一致。编辑器自己的逻辑文件和 RML 布局文件分离，视口与时间轴内部布局由引用的组件维护。内置布局修改后需要重建并重启 Editor；不自动覆盖已保存的布局。源码与维护入口见 动画与时间轴专题。

动画资产编辑器提供自己的菜单和工具栏，并在一个窗口内同时显示 Preview、Timeline 与 Details。Preview 始终保留在顶层编辑器根中，Timeline 和 Details 可以在该根内重新停靠或变成游离 Tab。Preview 渲染当前资产编辑器持有的临时 World，使用与 Mesh、Skeleton 编辑器相同的 3D Viewport 布局和场景渲染链路。临时 World 提供内容、Sky Light 和补充方向光，观察相机由 Viewport3D 独立持有；右键拖动环绕、中键拖动平移、滚轮缩放，Focus 重新取景。动画播放只更新模型姿态，不会每帧重置相机；临时 World 不改写资产或主 World。

在 Content Manager 中单击资源只选择它；双击 SkeletalAnimation、Timeline 或 AnimationStateMachine 会按 AssetId 打开顶层资产编辑器。不同资产各自拥有独立实例；再次双击同一资产只聚焦原实例。Notify、播放头、Undo/Redo 和 dirty 状态均属于该资产实例。项目资产支持 Save，引擎来源资产保持只读。动画从关联 Skeleton 的 previewMeshId 取得默认预览网格；Details 可以为当前编辑器会话临时选择其他兼容网格，而不会改写动画资产。

Viewport 的 Transform 按钮和项目 Project Preview 按钮都通过引擎命令执行。项目可以扩展固定的 File 菜单、主 Toolbar 和 viewport CustomBar Surface，但不能创建新的顶层 Surface。

时间轴操作

播放、暂停、停止和回到起点位于 Timeline 面板内。时间轴自行维护并推进当前时间，向宿主编辑器发出时间变化事件。标尺由长短刻度构成；点击或拖动标尺可连续定位，也可以直接拖动当前时间的箭头。定位不会吸附到刻度或帧，拖拽开始时暂停，松手后继续保持暂停。播放到结尾停在末帧，再次播放从头开始。

动画编辑器无论播放还是拖拽，都仅更新预览姿态，完全忽略 Notify 执行。Notify 数据仍可编辑、撤销和保存。技能编辑器等插件可以在自己的编辑器中订阅时间轴事件，独立实现特殊预览。

世界与资源

场景支持实体、父子层级、变换、相机、导航、网格、材质和动画等内容。可以把一组实体保存为可重复使用的预制内容，并在其他场景中创建独立实例。

World 是主编辑器当前文档。双击另一个 World 会先处理当前 World 的未保存修改，再替换主 Viewport、Hierarchy、Inspector 和 Play 上下文；World 不创建独立资产编辑器。Prefab 则始终打开自己的顶层资产编辑器，不替换主 World。

Mesh、StaticMesh 和 SkeletalMesh 编辑器提供真实 3D Preview、几何统计、Source 和 Diagnostics。项目 Mesh 只允许修改默认 Material；顶点、索引、骨骼和蒙皮权重保持只读。Skeleton 编辑器显示骨骼树与兼容 Preview Mesh，项目 Skeleton 只允许修改 previewMeshId。Material 编辑器提供预览球并编辑 shader、baseColor、metallic 和 roughness。引擎来源资产统一只读。

主 Viewport 和独立 Game 共用 retained GPU scene。OpenGL 是默认后端，renderBackends: Both 构建也可以在启动时使用 --render-backend vulkan；静态网格会按资源复用 vertex buffer 并自动实例化，骨骼网格由 GPU skinning。网格、骨骼 section、Bounds 和拾取 BVH 缓存在 Intermediate/RenderCache，它们都是可删除、可重建的派生数据，不会覆盖源资产。

场景环境照明由 Sky Light 组件提供，可以在 Inspector 中编辑 Color 和 Intensity。所有已启用且层级激活的 Sky Light 会线性累加；场景没有有效 Sky Light 时不会自动补光，未被其他光源照亮的表面保持黑色。Sky Light 只表示照明，不创建天空盒或可见天空背景。

骨骼网格每个顶点最多保留 12 个蒙皮影响；单个骨骼 section 最多引用 256 根实际使用的骨骼，超出时引擎自动切分 section，资产本身没有 256 根骨骼上限。GPU 场景提交失败时会在日志和 Editor Console 中明确提示并回退到 CPU；无效资产仍报告错误，设备丢失不会被当作普通 fallback。CPU 继续负责拾取和 Gizmo，静态网格拾取使用派生 BVH。

通过只读 MCP 工具 render.describe 或资源 sharpengine://render 可以查看当前后端、实际 VSync/validation 状态、GPU 提交/CPU fallback、派生缓存命中和驻留字节，以及最近 240 帧的平均值和 P95。帧 timing 使用单调时钟。Editor 和 Game 默认启用 VSync；性能基准或明确接受画面撕裂时可以使用 --render-vsync=off，OpenGL 和 Vulkan 都会验证该请求确实生效，不能生效时启动失败而不是静默保留同步。Vulkan validation 默认关闭，只能在 Debug 构建通过 --render-validation=on 显式启用；OpenGL 或非 Debug 请求会直接失败。

源资源是可编辑内容的唯一依据；运行和发布过程中产生的构建结果可以重新生成。无法识别的内容会被保留并提示问题，不会悄悄变成可运行对象。

FBX 导入与导出

FBX 是导入来源格式。导入后，项目使用 SharpEngine 的骨骼、蒙皮网格和动画资产；FBX 文件应保留在 Content 之外的来源目录。需要来源校验时，在资产中记录 sourcePath 和 sourceSha256，引擎会验证来源文件是否仍然匹配。验证来源不代表当前资产编辑仍能由该来源还原。

导出使用语义等价规则。网格几何、坐标系和单位，骨骼层级与绑定姿态，蒙皮权重，以及动画的骨骼轨道必须保持等价。导出器可以重新组织 FBX 记录、压缩方式和未建模的元数据，因此导出文件的字节内容不需要与导入文件相同。

通过资产的 ExportFbx 或 AssetContent.ExportFbx 入口导出。当前内置路径只复制显式注册的原始 FBX 来源；对规范化 SharpEngine 资产会报告尚未接入 FBX writer 且不改写目标文件。接入 writer 后从当前 SharpEngine 数据重建文件。完成后重新导入导出文件并检查上述语义数据；重新导入检查通过才算完成格式验证。

跨骨骼组复用动画时，先用 SkeletalAnimationCompatibility.Validate 检查动画和蒙皮网格。A 动画直接绑定 C 网格会被拒绝；使用 SkeletalAnimationRetargeter.Retarget 明确提供源/目标骨骼映射后，会生成指向 C 骨骼的新动画资产，再按普通兼容性规则与 C 蒙皮网格组合。当前 Retarget 不自动猜测骨骼、不做 IK 或比例补偿，FBX writer 仍未接入。

控制与移动

让角色或其他对象接受玩家或 AI 的控制，并按照移动意图在场景中移动。控制来源和移动能力彼此独立，因此同一套移动行为可以服务不同的控制方式。

当多个控制来源指向同一个对象时，引擎会按照优先级选择一个来源，保证结果稳定。对象不可用、控制冲突或控制暂时失效时，运行状态会显示相应诊断。

引擎默认示例包含 prefabs/capsule-character 胶囊体角色 Prefab，并已实例化到引擎的 Content/Worlds/Main.sworld。在编辑器按 Play 后点击 Viewport 使其获得焦点，使用 WASD 移动角色；Stop 会丢弃运行时位置变化。

示例 Prefab 和主场景使用 UEFN mannequin 骨骼角色，状态机会根据移动速度在 Idle、Walk、Run 之间切换，并保留 Jump 状态入口；胶囊只作为不可见的 Trace 碰撞体，随角色移动。状态机和动画依赖加载失败时会保留诊断，不会静默回退到错误 Clip。Content Manager 双击引擎提供的 AnimationStateMachine 预设会打开独立顶层动画资产编辑器并显示状态与过渡图；该引擎预设保持只读。验证入口与范围见下方专题文档。

需要“模式 + 修饰器 + 根运动归属”这种组合式移动时，使用引擎提供的移动组合点，或直接启用 Plugins/CharacterMovement 插件。插件提供移动权威、Walking/Falling 两个可替换模式，以及 Jump、Sprint、SpeedLimit 三个有序修饰器；同实体的 engine.movement 会转为 MOVEMENT_OVERRIDDEN，Transform 只由权威写入。插件为项目级 opt-in：在项目清单的 plugins 登记 engine://Plugins/CharacterMovement/CharacterMovement.sharpplugin 后重建项目即可，引擎默认内容不引用它。

功能边界、可观察状态和使用限制见 控制、可控制目标与移动专题文档。

输入与 UI

现有 RML 布局可以由代码在当前 UI 实例中增加或删除容器、文本、按钮和输入框，并绑定点击或值变化事件；也可以挂接 Viewport3D、Timeline 等功能提供的子布局。动态内容随实例刷新保留，输入框保留焦点和光标；关闭后释放，不改写原始布局，不改变资产 dirty 或 Save。父级只操作自己的容器，子功能通过公开接口定制。接入示例与限制见 运行实例 UI 组合。

键盘和鼠标会先交给当前获得焦点的界面。界面可以处理点击、滚动、文本输入和指针捕获；未被界面使用的输入再交给编辑器或游戏逻辑。File > Engine Settings > Shortcuts 是引擎快捷键的唯一来源：F5 播放或暂停，F8 停止，Ctrl+S 保存，Ctrl+Z 撤销，Ctrl+Y 或 Ctrl+Shift+Z 重做，Esc 释放游戏指针捕获；同一页还可修改 Viewport 的主导航键（默认 W/A/S/D/Q/E）、方向键备用导航键和加速修饰键（默认 Shift）。每个快捷键由主键加精确修饰键组成，改键后立即生效，不需要重启；重复的按键组合会被拒绝并在页面中标出，主键选择 None 表示不绑定。

快捷键属于 Editor 路由，无论焦点在视口、层级、分割条还是文本输入框内都会先被编辑器处理；只有界面处理了且编辑器没有对应快捷键的输入才会继续交给游戏。因此文本输入框内的 Ctrl+Z 由编辑器撤销，而不是输入框自身的编辑历史。

快捷键与工具栏、菜单执行的是同一条 command：改键只改变触发方式，不改变命令本身，因此快捷键与对应按钮的可用状态始终一致（按钮变灰时按快捷键也不会执行，但按键仍由编辑器消费，不会漏给游戏）。

快捷键按作用域冒泡：当前获得焦点的资产编辑器会先拿到 Save/Undo/Redo，消费后立即停止；它不消费（例如文档只读）时才继续冒泡到全局编辑器层。因此在资产编辑器里按 Ctrl+S 保存的是该资产，在主窗口里按 Ctrl+S 保存的是 World。作用域只接受来自自己窗口的按键事件，其他窗口的按键不会误触发。

编辑器界面和运行时界面都可以使用统一的操作映射，因此同一个操作在不同界面中能够保持一致的响应方式。Play 或 Pause 时，Viewport 的相机导航、选择和 Gizmo 不再接收游戏输入；输入只作用于运行时逻辑，Stop 后恢复编辑操作。

Player Prefab 使用独立第三人称相机和 Player 输入映射。鼠标调整镜头朝向，WASD 移动；默认站立时转动相机不转动人物；WASD 始终按相机水平朝向计算移动方向，角色根节点按该方向转身，Mesh 保留固定局部旋转并随角色一起转动。点击 Play 后可直接操作，Esc 释放光标（默认值，可在 Shortcuts 中改键），点击视口重新捕获。暂停、停止、失焦会释放光标并清空按键状态。游戏捕获指针期间，真实鼠标移动只驱动游戏，不再让编辑器界面产生 hover、拖拽或分割条缩放；Click Play 时也会清除编辑器残留的悬停与捕获状态。相机当前不提供遮挡避让。

项目动画 Details 中的 Root Motion 开关开启时让根位移驱动角色实体；关闭时显示原地动画并由移动组件控制位移。跳跃高度也随该开关处理，原始轨道不会删除。根设置与 Notify 共用撤销/重做，Save 才写入源资产；引擎内置动画保持只读。详见 控制与移动和动画。

Content Manager 的右键菜单由该浏览器实例自己提供：选中项目资产后可以删除它。删除只对该面板自己的选中生效，引擎资产、插件声明资产、只读资产、Play 期间以及当前打开的 World 都会被拒绝（菜单项显示为不可用）。执行前会弹出确认对话框，默认按钮是取消；完成后同时移除清单条目和源文件，失败时清单恢复原样。

StyleSheet 编辑器直接维护 RCSS 文本权威源，显示规则预览、引用该样式的 RML 文档和语法诊断。InputAction 与 InputMappingContext 使用结构化表单；Context 编辑器支持 bindings 的增删以及 action、control、scale、modifier、route 和 priority 编辑。无效引用、非法 Control 或未知枚举不会进入 dirty 文档。

设置与模块

开发功能采用组合式架构：基础能力和完整组合都可通过各自公共接口复用，上层只关心组合后的能力。功能定义与模板可以复用，进度等可变数据归属于每次使用的实例；嵌套子实例由所属组合驱动。组合插槽通过领域能力类型限制可接受的功能，Module 和 Plugin 仍承担构建、发现与分发职责。参见 组合式开发架构。

引擎设置和项目设置使用统一的属性面板编辑。修改会即时检查有效性，支持撤销、重做和恢复，保存后才会成为项目内容。Engine Settings / Shortcuts 列出全部引擎快捷键并在修改后立即重新绑定；Engine Settings / Navigation 保留 Invert Y Axis。

功能模块可以只服务编辑器、只服务运行模式，或同时服务两者。启动时会按照依赖关系载入模块，停止时会按相反顺序清理。

网络与 Dedicated Server

网络模块提供版本化 Schema、服务器 Command 路由、幂等结果和基于 RuntimeFrame 的完整快照/字段差分。DedicatedServerSession 使用现有 RuntimeWorld 的固定 Tick 和提交边界运行权威模拟。

UdpNetworkTransport 提供可运行的 C# UDP 收发，支持可靠有序投递、快照 ACK、连接超时和 payload 预算。服务器在 World 线程处理入站 Command，客户端只有在 Schema 指纹匹配并完成握手后才能发送 Command。项目默认只生成 Editor/Game；需要 Dedicated Server 时，在 Windows 资源管理器中右键项目的 .sharpproject 文件，选择 Add Server Target（Windows 11 可先选择“显示更多选项”）。该操作自动保存 Target 并重新生成工程文件，Rider 重新加载 solution 后即可使用 Server Target。QUIC、生产认证和客户端预测仍是后续工作。使用方式和验证命令见 网络、属性同步与 Dedicated Server 基础。

验证边界

功能验证分为内容检查、编辑器检查、运行检查、构建检查和发布包检查。某一层通过，只能说明该层的行为符合预期，不能替代其他层的验证。

每个功能页面都会说明适用的验证范围和已观察到的结果；遇到问题时，优先查看对应功能的诊断信息和验证记录。

引擎构建输出只允许 Debug、Development、Shipping 配置和 Editor、Game、Server、Tools target。验证截图、临时项目和隔离证据应写入 Saved/Validation；不得用 MSBuild 属性在 Binaries 或 Intermediate 中创建自定义验证目录。非法覆盖会在 restore/build 生成文件前以 SEOUTPUT001–SEOUTPUT014 拒绝。

数据资产

项目可以用 C# 数据类型定义独立的配置资产，将同一种配置类型保存为多个 .sdataasset 文本资源，并通过稳定资产 ID 加载。字段约束和直接资源引用会在加载时校验。抽象基类可以复用字段，具体派生类各自声明资产类型；sealed 不是必需的。

DataAsset 使用一套通用反射编辑器，不要求每个派生类型实现专用 UI。编辑器从 DataAssetTypeDescriptor.Properties 和 JSON Schema 生成字符串、数值、布尔、枚举、资产引用及 JSON 复合字段控件，并执行 Required、Minimum、Maximum 和引用类型校验。所有修改拥有独立 revision、Undo/Redo、dirty 和原子 Save。Editor 项目代码重载会重新发现具体类型，并更新表单、assets.describe 与 sharpengine://assets 的 Schema。使用方法和验证边界见 数据资产专题。

本版更新

修复 Rider 启动与构建配置脱节：每个 Debug、Development、Shipping 启动项现在拥有固定配置的 Target 与独立启动文件。选择 Debug Editor 会构建并启动 Debug Editor，即使全局解决方案选择 Development；普通 Build Solution 仍遵循全局配置。旧项目重新生成并加载解决方案后，选择新的配置专属启动 Target。重新构建前先停止占用该输出的编辑器。

新增构建后端选项：项目顶层 renderBackends 可设为 OpenGL 或 Both。新项目默认只编译 OpenGL，无需 Vulkan SDK；已有项目省略配置时保留双后端。修改后重新生成 Rider 项目文件，或通过构建命令 -RenderBackends 临时覆盖。两种构建均默认以 OpenGL 启动；只有 Both 构建接受 Vulkan 启动参数。切换构建会替换共享引擎输出，需重新构建并重启。详见 渲染后端与构建选择。

收紧编辑文档的事务边界：扩展应通过 EditSelectedEntity 或 EditWorld 修改候选数据，成功后统一进入撤销、重做和保存流程；直接修改已归属编辑会话的实体会被拒绝。Runtime 普通字段赋值保持支持。Dedicated Server 在模块子系统就绪后才创建 World，并按所有者推进和释放生命周期。同实体存在移动权威时 NavAgent 暂停移动并报告 NAV_MOVEMENT_AUTHORITY，停用或移除权威后恢复；导航尚未自动接入角色移动意图。

Content Manager 的资产删除成为该面板自己拥有的命令：命令与右键菜单项由浏览器实例注册，只对该实例的选中求值，不进入全局命令表；执行仍由拥有资产清单的编辑器工作流完成。判定拒绝、清单与文件同事务提交、失败回滚。全局命令保留给 MCP 与显式 UI 注册使用。

引擎快捷键集中到 File > Engine Settings > Shortcuts：F5/F8、Ctrl+S、Ctrl+Z、Ctrl+Y、Ctrl+Shift+Z、Esc 与 Viewport 导航键都可改键并立即生效；编辑器路由不再被 RmlUi 消费吞掉，焦点在文本输入框时 F5 等快捷键仍然可用。快捷键按获得焦点的文档作用域冒泡：资产编辑器先消费 Save/Undo/Redo，不消费才落到全局 World 层。Play 捕获指针后真实鼠标只作用于游戏，不再触发编辑器 hover 与分割条拖拽；释放捕获后编辑器会重新取得激活，避免后续按键落到其他窗口。Esc 取代 Shift+F1 作为默认释放手势。

内置 Player 改为相机参考移动：站立转动相机不改变人物朝向，WASD 按镜头水平朝向生成移动意图，角色根节点转向该方向，模型保留局部轴修正。现有项目实例可启用 FaceMoveDirection 选择此策略。

骨骼动画与状态机编辑器由独立 Animation.Editor 模块管理，复用下层 Timeline、Viewport 和布局基础设施。骨骼动画保留播放、预览模型、Root Motion、Notify、撤销与保存；状态机保留只读三面板显示，其布局由独立文件维护。使用新模块需重建并重启 Editor。

增加 UI 实例动态组合：在已有布局上通过代码添加/移除基础控件和子布局，绑定事件；共享布局定义保持只读。隔离 Editor 验证覆盖真实点击、连续输入、中部插入、刷新、实例隔离与源文件不变。

骨骼动画从通用 Timeline 编辑器中分离，专用编辑器以一份逻辑文件和一份布局文件组合 Viewport3D、Timeline 及预览 World。共享 UI 模板支持类型化子布局插槽，每个资产仍拥有独立播放、相机和 Dock 实例。

确定组合式开发基线：无环依赖、接口封装、模板与实例数据分离、类型化组合插槽和内部实例调度归属。同步修正开发技能中的旧版本兼容、删除引用与 Runtime 写入约定，并统一手册结构校验入口。该更新记录开发约束，不代表现有功能已完成全仓组合迁移或运行验收。

3D 预览按基础设施金字塔组合：通用 Viewport3D 提供显示与导航，World 作为内容挂接；同一个 World 可被多个视口独立观察，World 没有 Camera 实体也能预览。主场景视口继续使用既有事务与 Undo 路径。

通用资产 3D Viewport 的右键拖动方向与主场景视口默认方向一致：向右拖动向右环绕，向下拖动抬高相机。项目选择器随窗口宽高调整布局与封面高度，窄窗口将最近项目排列在详情上方，内容溢出时可滚动访问操作按钮。

修复 OpenGL 下打开和操作多个资产编辑器时，界面更新后读取 UI 快照可能导致崩溃的问题。

启动入口与插件选择：无项目进入使用引擎 RmlUi 与现有视觉方案的轻量项目选择器；静态预览不运行项目代码。新增默认插件的项目覆盖、依赖变更预览和原子保存；插件分析位于 Editor 内。更改需要重建项目并重启 Editor。

资产预览统一复用 3D Viewport 布局并渲染编辑器持有的临时 World；时间轴内置播放控件、连续刻度标尺和可拖拽时间箭头，拖拽后保持暂停。动画预览不执行 Notify。
